RSS新着収集スクリプト
=========================

課題
-------------------------

情報収集が十分にできていない。  
情報共有の仕組みはある。ただし、投稿は手作業で行っており、運用負荷が高い。  
運用の属人化は、情報の偏りにつながります。  
背景と制約は[課題](issue.md)を参照してください。

設計
-------------------------

課題を解決する仕組みとして、各自が手軽に情報収集できる状態を作ります。  
その手段として、ニュースサイトなどが提供するRSS/Atomフィードを利用します。  
RSS/Atomフィードを定期的に取得し、新着だけを`news.md`に書き出す仕組みです。  
これにより、情報共有の運用負荷を減らし、情報の偏りを抑えることを目指します。  
設計の詳細は[概要設計](design.md)を参照してください。

実装
-------------------------

設計を具体的に落とし込んだスクリプトが、zx版、PHP版、Python版の3つです。  
どれか1つを選んで使います。

必要な環境
-------------------------

使う版に応じて、次の環境が必要です。

- zx版(`news.mjs`): Node.js 24以上と、[zx](https://google.github.io/zx/)
    - 初回の実行時に、依存パッケージ(`fast-xml-parser`、`nunjucks`)を`npm install`で自動導入します。
    - 導入にはネットワークが必要です。
- PHP版(`news.php`): PHP 8.2以上
    - 拡張の`curl`、`dom`、`libxml`、`mbstring`、`pdo_sqlite`を使います。
    - 初回の実行時に、TwigをComposerで`vendor/`へ自動導入します。
    - Composerが必要です。導入にはネットワークが必要です。
- Python版(`news.py`): Python 3.11以上
    - Python 3.9は2025-10-31にEOL済みのため、3.11以上を使います。
    - 初回の実行時に、Jinja2をuv優先で`python-vendor/`へ自動導入します(uvがなければpipを使います)。
    - 導入にはネットワークが必要です。
    - タイムゾーンデータがない環境では、`tzdata`パッケージを導入してください。

使い方
-------------------------

### 1. フィードの一覧を用意する

`feeds.sample.txt`を`feeds.txt`にコピーし、取得したいフィードのURLを書きます。

```bash
cp feeds.sample.txt feeds.txt
```

- 1行に1URLを書きます。
- URLの後ろに空白かタブを入れて、表示名を書けます(省略できます)。
    - 表示名は、`news.md`の見出しになります。
    - 省略すると、フィード自身のタイトルを使います。
        - GitHubのリリースのフィードは、`Release notes from ...`のようなタイトルになるため、表示名を付けると読みやすくなります。
- `#`で始まる行は、コメントです。
- 対応する形式は、RSS 2.0とAtom 1.0です。
- 同じ記事が複数のフィードにある場合は、上に書いたフィードの記事が残ります。

### 2. スクリプトを実行する

使う版のコマンドを、新着の出力先にしたいディレクトリ(ワーキングディレクトリ)で実行します。

```bash
# zx版
zx /path/to/rss-news/news.mjs

# PHP版
php /path/to/rss-news/news.php

# Python版
python3 /path/to/rss-news/news.py
```

- `feeds.txt`は既定でスクリプトのあるディレクトリに置き、`NEWS_FEEDS_PATH`で変更できます。
- `news.db`は既定でスクリプトのあるディレクトリ、`news.md`と`news/`は実行したディレクトリに出力されます。
- `news.db`、`news.md`、`news/`のパスは、`NEWS_DB_PATH`、`NEWS_OUTPUT_PATH`、`NEWS_DIR_PATH`で変更できます。
- 3つの版は、同じ`feeds.txt`と`news.db`を使えます。途中で版を切り替えても、記録は引き継がれます。

### 3. 結果を読む

実行すると、次のファイルができます。

- `news.md`: 今回の新着です。実行のたびに全体を上書きします。
    - 出力ファイルのパスは`NEWS_OUTPUT`、出力形式は`NEWS_TEMPLATE`で変えられます。既定は`news.md`です。
- `news/`: 新着があった実行ごとの`news.md`の複製です。前回までの新着は、ここから読めます。
    - ファイル名は、`news/2026-10-10_0839.md`のように、取得日時(日本時間)になります。
    - ディレクトリは`NEWS_DIR_PATH`で変更できます。
- `news.db`: 取り込み済みの記事の記録(SQLite)です。手で編集しません。
    - パスは`NEWS_DB_PATH`で変更できます。

`news.md`の例です。

```markdown
新着3件(取得: 2026-10-10 08:39)

前回までの新着は、`news/`の複製を参照してください。

### Publickey

- [記事タイトル](https://example.com/article1) (2026-10-09)

### 取得に失敗したフィード

- https://example.com/feed.xml: HTTP 404
```

- 新着が0件の場合も、`news.md`は上書きされます。1行目が「新着0件」になります。
- 取得に失敗したフィードがある場合は、末尾にURLと理由が載ります。
- 失敗しても、他のフィードの処理は続きます。

出力テンプレート
-------------------------

出力形式は、テンプレートで変えられます。
既定はMarkdownで、次の3種類を用意しています。

- Markdown: `templates/news.md.j2` / `news.md`
- HTML: `templates/news.html.j2` / `news.html`
- テキスト: `templates/news.txt.j2` / `news.txt`

3つの版は、同じテンプレートを使います。
形式を変える場合は、各スクリプトの`NEWS_TEMPLATE`と`NEWS_OUTPUT`を変更します。

テンプレートは、Twig、Jinja2、Nunjucksで共通に使える記法で書きます。
使う記法は、次の3つです。

- `{{ 変数名 }}`: 値を埋め込みます。
- `{% for 変数 in 配列 %}...{% endfor %}`: 配列を繰り返します。
- `{% if 条件 %}...{% else %}...{% endif %}`: 条件によって出し分けます。

テンプレートで使える値は、次のとおりです。

- `newsCount`: 新着の件数
- `fetchedAt`: 取得日時(例: `2026-10-10 08:39`)
- `newsDir`: 過去の複製を置くディレクトリ名
- `feeds`: フィードの配列
    - `name`: フィードの表示名
    - `title`: フィード自身のタイトル
    - `url`: フィードのURL
    - `entries`: 記事の配列
        - `title`: 記事のタイトル(生の値)
        - `url`: 記事のURL(生の値)。URLがない場合は空文字
        - `hasUrl`: URLがある場合だけ`true`
        - `isHttpUrl`: URLがhttpまたはhttpsの場合だけ`true`
        - `titleMarkdown`: Markdown用にエスケープしたタイトル
        - `urlMarkdown`: Markdown用にエスケープしたURL
        - `date`: 記事の日付(例: `2026-10-09`)。日付がない場合は空文字
        - `hasDate`: 日付がある場合だけ`true`
        - `dateSuffix`: 日付がある場合だけ`(2026-10-09)`。ない場合は空文字
- `failures`: 取得に失敗したフィードの配列
    - `url`: フィードのURL
    - `reason`: 失敗の理由
- `hasFailures`: 取得に失敗したフィードがある場合だけ`true`

`titleMarkdown`と`urlMarkdown`は、既定のMarkdownテンプレート用です。
HTMLとテキストでは、`title`および`url`をそのまま使います。

HTMLを出力する場合は、出力ファイル名の拡張子を`.html`または`.htm`にします。
この場合、テンプレートの値は自動でHTMLエスケープされます。
`news/`の複製の拡張子は、出力ファイル名の拡張子に合わせます。

`NEWS_TEMPLATE`と`NEWS_OUTPUT`は、スクリプト内の定数です。
`NEWS_TEMPLATE_PATH`と`NEWS_OUTPUT_PATH`は、実行時に設定を上書きする環境変数です。
環境変数が設定されている場合は、定数より優先します。

- テンプレートの相対パスは、スクリプトのあるディレクトリが基準です。
- 出力ファイルの相対パスは、ワーキングディレクトリが基準です。

初回の実行について
-------------------------

初めて取得するフィードは、記事が大量に残っています。
そのため、初回は直近7日以内の記事だけを新着として出します。
それより古い記事は、`news.md`には出さず、記録だけします。
次回以降に、古い記事が新着として出ることはありません。

動作を確認するときは、続けて2回実行してください。
2回目の新着が0件になれば、正常です。

設定を変える
-------------------------

設定は、各スクリプトの先頭にある定数で変えます。
一部は環境変数でも上書きできます。
3つの版で、定数名と意味は共通です。

### 定数

定数は、スクリプトを編集して変更します。

- `KEEP_DAYS`: 古い記事を削除するまでの日数です。0なら削除しません(初期値は0)。
- `INITIAL_DAYS`: 初回取得で、新着として出す期間の日数です。0なら絞りません(初期値は7)。
- `NEWEST_FIRST`: フィード内の並び順です。新しい順なら`true`です(初期値は`true`)。
- `TIMEZONE`: 画面に出す日時のタイムゾーンです(初期値は`Asia/Tokyo`)。
- `FETCH_TIMEOUT_SECONDS`: フィード1本あたりの取得のタイムアウト秒数です(初期値は30)。
- `NEWS_DIR`: 過去の`news.md`の複製を置くディレクトリです(初期値は`news`)。
    - 相対パスは、ワーキングディレクトリが基準です。
    - 絶対パスも指定できます。
- `SUMMARY_MAX_LENGTH`: 記事の概要として保存する最大文字数です(初期値は500)。
- `NEWS_TEMPLATE`: 出力テンプレートのファイル名です(`templates/`からの相対パス。初期値は`news.md.j2`)。
- `NEWS_OUTPUT`: 出力ファイルの既定パスです(ワーキングディレクトリからの相対パス。初期値は`news.md`)。
- `AUTO_INSTALL_DEPENDENCIES`: 依存パッケージが不足しているときに、自動で導入するかです(初期値は`true`)。
    - `false`にすると、自動導入せず、必要なコマンドを案内します。

`KEEP_DAYS`を設定すると、フィードに載らなくなった記事の記録が、指定した日数のあとに削除されます。
フィードに載っている間は削除されません。

### 環境変数

環境変数は、スクリプトを編集せずに実行時だけ設定を変えたい場合に使います。

- `NEWS_TEMPLATE_PATH`: 実行時にテンプレートのパスを上書きします。
    - 相対パスは、スクリプトのあるディレクトリが基準です。
    - 設定時は`NEWS_TEMPLATE`より優先します。
- `NEWS_OUTPUT_PATH`: 実行時に出力ファイルのパスを上書きします。
    - 相対パスは、ワーキングディレクトリが基準です。
    - 設定時は`NEWS_OUTPUT`より優先します。
- `NEWS_FEEDS_PATH`: 実行時にフィード設定ファイルのパスを上書きします。
    - 相対パスは、スクリプトのあるディレクトリが基準です。
- `NEWS_DB_PATH`: 実行時にDBのパスを上書きします。
    - 相対パスは、スクリプトのあるディレクトリが基準です。
- `NEWS_DIR_PATH`: 実行時に複製ディレクトリのパスを上書きします。
    - 相対パスは、ワーキングディレクトリが基準です。

### 複数の版を並列で実行する

版ごとに`NEWS_FEEDS_PATH`、`NEWS_DB_PATH`、`NEWS_OUTPUT_PATH`、`NEWS_DIR_PATH`を変えると、3つの版を並列で実行できます。

定期実行する
-------------------------

定期実行は任意です、手動で実行してもかまいません。

cronで実行する場合は、crontabに1行登録します。  
`cd`で指定したディレクトリが、`news.md`の出力先になります。  
フィードの更新が頻繁なため、1日2回以上を目安にしてください。

```text
# zx版
0 11,17 * * * cd ~/rss-news && zx news.mjs >> run.log 2>&1

# PHP版
0 11,17 * * * cd ~/rss-news && php news.php >> run.log 2>&1

# Python版
0 11,17 * * * cd ~/rss-news && python3 news.py >> run.log 2>&1
```

- 上の例は、毎日の11時と17時に実行します。
- 使う版の1行だけを登録します。
- `~/rss-news`は、スクリプトと`feeds.txt`を置いた場所に書き換えます。
- `>> run.log 2>&1`で、実行ログを`run.log`に追記します。
- 平日だけなら、曜日の欄を`1-5`にします。
- cronが動くLinux環境で実行することを前提にします。
- cronの設定方法やサービス名は、利用するLinux環境のドキュメントを参照してください。

困ったとき
-------------------------

- 「feeds.txtを読めません」「有効なURLがありません」と出る場合は、使用している`feeds.txt`が存在するか、URLが書かれているかを確認してください。
- 「取得に失敗したフィード」に`HTTP 404`と出る場合は、フィードのURLが変わっていないか確認してください。
- 同じく`parse error`と出る場合は、URLがRSS 2.0またはAtom 1.0のフィードを指しているか確認してください。
- 同じく`timeout`や`network error`と出る場合は、ネットワークの接続を確認してください。
- `feeds.txt`から消したフィードの記事は、記録からも消えます。同じフィードを書き直すと、初回取得として扱われます。
- 記録を最初からやり直したい場合は、使用している`news.db`を削除してください。
- 「Composerが見つかりません」「Twigの導入に失敗しました」と出る場合は、`rss-news`で`composer install`を実行してください。
- 「uvまたはpipが見つかりません」「Jinja2の導入に失敗しました」と出る場合は、次のコマンドを実行してください。
    - `cd rss-news && python3 -m pip install --target python-vendor -r requirements.txt`
